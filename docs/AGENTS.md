本目录为一个 Notist 库。

## 目录结构

- `_logs`：日志文档
  所有的文件以 `YYYY-MM-DD {topic}` 格式命名。禁止引用该目录之外的内容，每一篇 log 文档的内容应该不受外部内容变化影响。
- `book`：使用指南文档（非目前焦点，低优先级）
- `designs`：设计文档
- `thoughts.not`：一些想法积累
- `draft.not`：临时性的草稿
- `todos.not`：一些已确定需要完成的任务

## 写作纪律

当需要严格控制模块顺序时，用 `00-xxx` 的形式来命名模块。

在目录性索引之外的正文内容中需要注意：
- 引用仅限依赖指向：本文使用了定义在别处的概念时，指向其定义处一次。
  判断标准：删掉引用后读者找不到本文所用概念的出处，才是必要引用。
- 禁止冗余的导航式引用：见 X 了解 Y、"本文与 X 各管一面"的分工声明、文件间相互提示。

### designs 写作纪律

- 确保内容准确、信息密度高、简明、易于阅读，在修改时要保证不存在重复或矛盾的问题。
- `designs/philosophy.not` 是用户手写的核心设计洞察与裁决，禁止 AI 修改、重写、摘要替换或调整其属性；即使其他实现或文档与它冲突，也只能修改冲突的其他文档。只有用户明确指定该文件的具体修改内容时，才可以编辑它。
- 禁止任何如“已废除”、“改为”、“不是...而是...”的表述，直接描述目标，不引入冗余无效信息
- 禁止滥用引用，只在必要时引用相关内容
- 禁止任何历史沿革性质的表述，只描述当前最新设计状态

## notist 属性

在本目录下，Notist 的一些属性标注含义约定如下：

| 属性 | 类型 | 含义 |
|------|------|------|
| `draft` | bool | 草稿内容 |
| `ai` | bool | 是否是由 AI 直接生成的内容 |
| `desc` | string | 简单描述/摘要 |
| `agents` | string | 对该 Node 生效的类 AGENTS.md 的提示，在操作对应 Node 前必须确保阅读并理解 |

在生成文档时，如果对应部分内容完全由 AI 生成，则必须标注上 `ai: true` 属性。
`draft: true` 的内容不应作为判断依据或拒绝理由，但是遇到存在矛盾的情况应该主动询问。
