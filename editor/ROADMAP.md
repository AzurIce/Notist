# 编辑器路线图

目标是具备本地编辑、可靠保存与实例间协作能力的一方编辑器。CRDT 从文档内核建立时参与单人和离线编辑，网络在本地编辑与恢复链路完成后接入。近期交付目标是完成阶段 3。

## 项目边界

编辑器位于同仓的 `editor/`，使用独立 Cargo workspace。语言栈、HTML 渲染和 CLI 位于根目录 `crates/`。编辑器通过应用接入层消费 Notist 语言能力，通用内核保持语言无关。

```text
editor/
  Cargo.toml
  app/                       Web 界面
  crates/
    editor-wasm/             Wasm 接入，当前包名 notist-editor
    editor-core/             通用 CRDT 文档内核，阶段 2 创建，名称暂定
  scripts/
  fixtures/
```

持久化与网络的具体实现由宿主提供；同步层处理授权、版本交换和操作补齐。原生监听节点等新增 crate 随对应阶段建立。

## 阶段 1：整理项目

范围：建立 `editor/` workspace，归置 Web 界面、Wasm crate、fixtures 和脚本，更新构建路径。

验收：Wasm 构建、fixture 生成和 native/Wasm 对拍通过；现有页面资源与模块路径完整。此阶段保持调试器功能。

## 阶段 2：CRDT 文档内核

范围：选择现成 CRDT 库并建立独立内核 crate；定义文档与写入者身份、历史代次、本地事务、因果版本、不可变文本快照、相对位置锚点与协作撤销。区分复制状态、可重建的分析数据、本地视图状态和临时 presence。

验收：两个内存副本在离线编辑、乱序和重复交付后收敛；撤销保留对方修改；锚点在并发插入、删除中遵循明确规则；native/Wasm 对同一操作序列得到一致结果。验证不依赖网络服务。

待定：Loro/yrs 选型、锚点删除行为、撤销分组与恢复范围、历史保留策略。先用实验验证这些语义，再固定公共接口。

## 阶段 3：本地编辑器

范围：CM6 接入文档内核；应用层组合 Notist 分析、诊断、补全和 HTML 预览；建立后台分析与结果版本管理。普通文本和 `.not` 共用编辑事务入口。

验收：持续编辑、IME、多选区和撤销正常；分析不阻塞输入；文档或依赖变化后，旧结果不会覆盖新状态；文本坐标在 UTF-8、UTF-16 与 CRDT 位置之间正确转换。

待定：CM6 与 Wasm 的事务接入方式，以及文档状态和分析任务的线程分配。

## 阶段 4：可靠保存

范围：宿主实现 CRDT 日志与快照持久化、恢复、普通文本导入导出和外部文件变更处理；分别记录当前状态、本地持久化状态与文本落盘状态。浏览器存储和文件系统各自实现宿主接口。

验收：已确认持久化的编辑在重启后恢复；保存期间新增编辑仍显示未保存；自身写回不形成监听循环；外部文件修改与未落盘编辑并存时不会被静默覆盖。

待定：旁挂历史的布局、历史丢失后的重新导入规则、Git 分支切换行为，以及历史压缩对锚点和撤销的影响。

## 阶段 5：两实例同步

范围：原生宿主支持显式设置监听 IP/端口和主动连接地址；浏览器使用主动连接参与双向同步。加入共享空间 token、读写授权、因果版本交换、缺失操作补齐、断线重连与临时光标同步。

验收：两个实例实时协作；断网后可独立编辑，重连后收敛；重复传输不产生重复编辑；未授权连接和写入被拒绝；界面区分本地保存与同步确认。

待定：传输协议、token 生命周期、节点身份、授权撤销与离线编辑的处理。节点发现、NAT 穿透与多跳转发留到后续范围评估。

## 阶段 6：工作区与多节点

范围：共享文件目录与稳定文件身份、重命名和删除、选择性文档同步、跨文档操作组织；在两实例协议上加入多节点转发和可选常驻中继。

验收：文件移动后仍定位同一文档；同名和删除/编辑冲突保留可恢复内容；三个以上节点在环路、重复交付和节点离线后仍收敛；操作只向有权限的订阅者转发。

待定：文档与目录的复制粒度、跨文档操作保证、转发中的原始写入者证明、成员管理、历史裁剪后的旧副本接入。自动发现、穿透和端到端加密按实际产品需求安排。

## 仓库拆分时机

语言接入稳定、编辑器有独立发布节奏，并且两边需要联合修改的频率显著降低时，再评估整体迁出 `editor/`。包含多个 crate 本身不要求独立仓库。
